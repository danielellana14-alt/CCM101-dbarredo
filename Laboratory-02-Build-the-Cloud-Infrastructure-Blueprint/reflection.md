# Mission Reflection

This laboratory helped me understand how the different components of cloud infrastructure work together. By investigating the KillerCoda Linux server, I was able to identify the operating system, kernel, CPU, RAM, storage, hostname, and network configuration. Using commands such as `lscpu`, `free -h`, `df -hT`, and `ip addr` gave me practical experience in examining a server environment instead of only learning these concepts theoretically.

Among the infrastructure components, I consider **compute resources** to be one of the most important because applications need CPU and memory to execute processes. However, compute cannot work independently because it depends on storage, networking, and the operating system to provide a complete working environment.

Linux plays an important role in cloud computing because it provides a stable operating environment for servers and applications. It also provides many useful command-line tools for monitoring and managing system resources. The KillerCoda activity allowed me to see how these tools can be used to investigate an actual Linux environment.

Technical documentation is important before deploying infrastructure because it provides a clear record of the resources, configurations, architecture, and decisions involved in a system. Good documentation can make troubleshooting, maintenance, and future improvements easier.

I learned several new skills during this laboratory, including Linux server investigation, identifying infrastructure resources, comparing AWS, Azure, and Google Cloud services, designing a basic cloud architecture, and organizing technical information using Markdown and GitHub.

My GitHub portfolio also improved because the laboratory added a complete cloud infrastructure project containing technical documentation, research, server investigation results, and an architecture diagram. This makes the portfolio more organized and demonstrates practical knowledge of cloud computing and documentation.
